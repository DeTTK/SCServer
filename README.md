# SCServer / Бскпкрафт

## Дисклеймер

Проект выложен для изучения и своих экспериментов. Продавать его, сборки на его основе и доступ к ним не надо. Если решите на этом зарабатывать — с правообладателями будете разбираться сами. Это не разрешение торговать чужой игрой и её ресурсами.

Права на оригинальный клиент, ресурсы и сторонние библиотеки остаются у их правообладателей. Лицензию на свой код пока не выбирали.

## Что где лежит

- `server/` — код Java-сервера.
- `client/` — загрузчик модов и правки совместимости клиента.
- `desktop/` — исходники лаунчера и окна управления сервером.
- `mods/` — исходники наших модов: транспорт, дроны, камера, HUD и остальное.
- `sdk/` — API для модов и простой пример `HelloMod`.
- `scripts/` — скрипты сборки и запуска.
- `docs/` — подробные инструкции, если коротких ниже не хватило.
- `build/` — сюда попадает собранное. Папка появится после сборки.
- `.local/` — местные настройки, зависимости и данные тестового сервера. В Git не отправляются.

Для игры нужны совместимые папки `Client`, `Server`, `Map` и установленный клиент Бскпкрафта. Игровых файлов и карты в этом репозитории нет. Пустой `git clone` их не скачает.

## Просто запустить локалку

Если готовый комплект уже есть:

1. Запускаете `Server/ServerManager.exe`.
2. Выбираете папку карты `Map`. Для игры на этом же компьютере указываете `127.0.0.1`, для друзей — IP компьютера в вашей сети.
3. Жмёте запуск и ждёте, пока сервер будет готов.
4. Открываете `Client/Launcher.exe`.
5. Вписываете адрес сервера, логин и путь к установленной игре. Для обычного готового комплекта адрес — `127.0.0.1:29545`.
6. Запускаете игру.

Если сервер на другом компьютере, вместо `127.0.0.1` нужен его IP. Для игры по сети используются TCP 29545/29546 и TCP/UDP 29547.

Останавливайте сервер кнопкой **«Сохранить и остановить»**. Сохранения готового комплекта лежат в `Server/data`.

## Собрать сервер самому

Нужны **JDK 17** и **Python 3.10+**. `java` и `javac` должны быть в `PATH`, либо задайте `JAVA_HOME`. Команды ниже выполняются из папки репозитория.

Проверить, что всё собирается:

```sh
python scripts/build.py test
```

Для игрового запуска нужны ресурсы из совместимого готового сервера. Подставьте свои пути:

```sh
python scripts/import_private_resources.py --server-jar "C:/LocalGame/Server/server.jar"
python scripts/build.py server --private-resources
python scripts/run_server.py --bundle "C:/LocalGame/Server" --map "C:/LocalGame/Map"
```

Так запустится **ваш `build/server.jar`**. Его сохранения лежат отдельно: `.local/server-state/data`. Оригинальная карта остаётся на месте.

У этого способа адрес по умолчанию — **`127.0.0.1:29544`**. В лаунчере укажите именно его. Если хотите играть с другого компьютера, добавьте к последней команде `--host IP_КОМПЬЮТЕРА`. Остановка — Ctrl+C, потом дождитесь завершения Java.

После `build.py test` перед игрой снова выполните `build.py server --private-resources`: тестовая сборка не содержит игровых ресурсов.

Лаунчер и окно сервера собираются на Windows командой `python scripts/build.py desktop`. Готовые EXE появятся в `build/desktop/`. Одних этих EXE для запуска мало — им нужны остальные файлы готового комплекта.

## Админки и кнопки

Для штатных админских окон нужны права администратора на сервере. В настройке готовой локалки они выдаются через `game.playerPermission=admin` в конфигурации сервера.

- **Alt** — штатное девменю.
- **I** — штатная выдача предметов.
- **Alt+R** — штатная выдача патронов.
- С модом `command-completion`: **Tab** дополняет команду в чате, **↑ / ↓** выбирают подсказку, **Esc** скрывает список.

Остальные кнопки относятся к модам. Если мод не установлен, одной кнопкой он не появится. Здесь указаны значения по умолчанию из исходников:

| Мод | Кнопки |
|---|---|
| `sc-vehicles` | **[ / ]** — выбрать машину, **F9** — создать выбранную (нужны права админа), **F8** — убрать свою |
| Тот же транспорт | **E** — сесть, **R** — двигатель, **G** — выйти, **J** — двери, **V** — выглянуть из окна / вернуться |
| `cinematic-camera` | **F7** — включить / выключить, **F6** — редактор, **F4** — поставить статичную камеру, **F3** — отдельный вид от первого лица |
| Та же камера | **F8** — следующий набор FP/TP, **F9** — сохранить пресет, **F10** — загрузить, **F11** — следующий слот |
| `network-replay` | **F12** — список реплеев |
| `weapon-workbench` | **J** — модификация оружия в руках |
| `fpv-drones` | **R** — арминг дрона; развёртывание — через действие предмета |

У камеры и машин совпадают F8/F9, у дверей и модификации оружия — J. Если ставите их вместе, разнесите кнопки в настройках модов через **Esc**. Настройки и кнопки зависят от версии конкретного мода.

В `mods/` лежат исходники. Общей команды, которая собирает весь этот набор разом, пока нет. Готовый клиент без модов сам их оттуда не подхватит.

## Как написать свой мод

Проще всего начать с готового примера:

1. Откройте `sdk/example/src/example/HelloMod.java`. Это обычный Java-класс с интерфейсом `ClientMod`.
2. Поменяйте код под себя. Для начала хватит сообщения в `onLoad` через `context.log(...)`.
3. В `sdk/example/stalcraft-mod.properties` задайте свой `id`, название и версию. Если переименовали класс — поправьте `main`, например `example.MyMod`.
4. Соберите:

   ```sh
   python scripts/build.py sdk
   ```

5. Возьмите `build/hello-mod.jar` и положите в папку `mods` совместимого клиента. Перезапустите клиент, сообщение из `onLoad` ищите в его логе.

Имя выходного JAR в этом скрипте пока остаётся `hello-mod.jar`, даже если внутри вы уже поменяли название мода. Имя файла `stalcraft-mod.properties` тоже не меняйте: его ищет загрузчик.

Основные методы мода:

- `onLoad` — загрузка и подготовка.
- `onInput` — клавиатура, мышь и геймпад.
- `onTick` — логика по тикам.
- `onFrame` — вызов каждый кадр, в том числе в меню.
- `registerSettings` — настройки во вкладке мода.
- `registerKeybinds` — регистрация кнопок.
- `registerHud` — элементы HUD.
- `onUnload` — убрать за собой при выгрузке.

Например, кнопку можно объявить так:

```java
public void registerKeybinds(KeybindRegistry keys) {
    keys.register("toggle", "Включить мой мод", 75); // K, код GLFW
}
```

Само действие пишется отдельно в `onInput`: состояние K можно проверить через `input.keyDown(75)`. Метод сообщает, что кнопка удерживается, поэтому для одного переключения на нажатие запоминайте её предыдущее состояние. Одна регистрация кнопки действие за вас не выполнит.

API лежит в [`sdk/api/szmods/api`](sdk/api/szmods/api), пример — в [`sdk/example`](sdk/example). К внутренним классам игры сразу лучше не лезть: там всё привязано к версии клиента.

Подробности запуска — [здесь](docs/QUICKSTART.md), текущие ограничения — [здесь](docs/STATUS.md). Баги и предложения кидайте в Issues: что делали, что ожидали и что получилось.
