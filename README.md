## Дисклеймер

Проект выложен для изучения и своих экспериментов. Продавать его, сборки на его основе и доступ к ним не надо. Если решите на этом зарабатывать — с правообладателями будете разбираться сами. Это не разрешение торговать чужой игрой и её ресурсами.

Права на оригинальный клиент, ресурсы и сторонние библиотеки остаются у их правообладателей. Лицензию на свой код пока не выбирали.

## Что где лежит

- `server/` — код Java-сервера.
- `client/` — загрузчик модов и правки совместимости клиента.
- `launcher/` — нативный Rust + Slint лаунчер и supervisor.
- `bootstrap/inputs/`, `map/data/` — закреплённые входы полной игровой сборки.
- `sdk/` — API для модов и простой пример `HelloMod`.
- `scripts/` — скрипты сборки и запуска.
- `docs/` — подробные инструкции, если коротких ниже не хватило.
- `build/` — сюда попадает собранное. Папка появится после сборки.
- `.local/` — местные настройки, зависимости и данные тестового сервера. В Git не отправляются.

Рабочий канал игры — `main` → `build-main`. Разработка идёт в `test` → `build-test`. Для переноса изменений в рабочий канал откройте PR из `test` в `main`. Build-ветки генерирует CI. [Как устроена доставка](delivery/README.md).

## Скачать и запустить

1. [Скачайте BSCPCRAFT.exe](https://github.com/DeTTK/SCServer/releases/latest/download/BSCPCRAFT.exe) и положите его в отдельную папку.
2. Выберите в лаунчере корень установленного STALCRAFT, папку данных и ник.
3. Оставьте ветку `main` и нажмите «Установить игру». Лаунчер скачает Java, клиент, сервер и базовую карту.
4. Выберите мир и запускайте игру. Для подключения к другу вставьте IP или приглашение в строку адреса.

Лаунчер проверяет обновления игры и самого EXE. Для пробной игровой сборки выберите `test` в настройках. При переходе с `launtest` сохраните существующий portable-профиль и выберите `main` вручную. Старую папку с сохранениями из C# поставки сохраните отдельно.

## Собрать сервер самому

Если непонятно, какую папку или версию игры выбирать, см. [раздел быстрого старта](docs/QUICKSTART.md#какую-версию-игры-выбирать).

Нужны **JDK 17** и **Python 3.10+**. `java` и `javac` должны быть в `PATH`, либо задайте `JAVA_HOME`. Команды ниже выполняются из папки репозитория.

Проверить, что всё собирается:

```sh
python scripts/build.py test
```

Для игрового запуска нужны ресурсы из совместимого готового сервера. Подставьте свои пути:

```sh
python scripts/import_private_resources.py --server-jar "C:/LocalGame/Server/server.jar"
python scripts/build.py server --private-resources
python scripts/run_server.py --bundle "C:/LocalGame/Server" --map "C:/LocalGame/Map"
```

Так запустится **ваш `build/server.jar`**. Его сохранения лежат отдельно: `.local/server-state/data`. Оригинальная карта остаётся на месте.

У этого способа адрес по умолчанию — **`127.0.0.1:29544`**. В лаунчере укажите именно его. Если хотите играть с другого компьютера, добавьте к последней команде `--host IP_КОМПЬЮТЕРА`. Остановка — Ctrl+C, потом дождитесь завершения Java.

После `build.py test` перед игрой снова выполните `build.py server --private-resources`: тестовая сборка не содержит игровых ресурсов.


## Размер персонажа

В свежую сборку встроено изменение размера: `/scale 0.5` — уменьшить себя, `/scale 2` — увеличить, `/scale reset` — вернуть как было. Для другого игрока: `/scale "Ник" 2`. Нужны права админа. Размер от `0.25` до `4`, сохраняется после выхода.

Меняются тело, хитбоксы, высота камеры и скорость движения. Видно от первого лица и другим игрокам. Анимации учитывают размер: гигант делает обычные шаги, просто длиннее. В транспорте менять размер нельзя, под низким потолком сервер не даст вырасти.

Чтобы заработало у всех, обновите и сервер, и клиент через обновления лаунчера. Карта и персонажи сохранятся. В `mods` ничего добавлять не нужно. [Подробности и сборка](docs/character-scale.md).

## Кейсы и подсказки команд

Кейсы открываются из обычного инвентаря. Выпавшие вещи остаются в рюкзаке, ключи списываются вместе с кейсом. Если не хватает места или ключа, ничего не теряется. [Подробности и ограничения](docs/LOOTBOXES.md).

В комплект входит автодополнение: начните писать команду в чате, нажимайте **Tab** для подстановки и **Shift+Tab** для предыдущего варианта. **↑/↓** выбирают подсказку, **Esc** скрывает список. Лаунчер добавит мод и в уже установленную локалку. [Исходники и сборка](client/command-completion/README.md).

## Как написать свой мод

Проще всего начать с готового примера:

1. Откройте `sdk/example/src/example/HelloMod.java`. Это обычный Java-класс с интерфейсом `ClientMod`.
2. Поменяйте код под себя. Для начала хватит сообщения в `onLoad` через `context.log(...)`.
3. В `sdk/example/stalcraft-mod.properties` задайте свой `id`, название и версию. Если переименовали класс — поправьте `main`, например `example.MyMod`.
4. Соберите:

   ```sh
   python scripts/build.py sdk
   ```

5. Возьмите `build/hello-mod.jar` и положите в папку `mods` совместимого клиента. Перезапустите клиент, сообщение из `onLoad` ищите в его логе.

Имя выходного JAR в этом скрипте пока остаётся `hello-mod.jar`, даже если внутри вы уже поменяли название мода. Имя файла `stalcraft-mod.properties` тоже не меняйте: его ищет загрузчик.

Основные методы мода:

- `onLoad` — загрузка и подготовка.
- `onInput` — клавиатура, мышь и геймпад.
- `onTick` — логика по тикам.
- `onFrame` — вызов каждый кадр, в том числе в меню.
- `registerSettings` — настройки во вкладке мода.
- `registerKeybinds` — регистрация кнопок.
- `registerHud` — элементы HUD.
- `onUnload` — убрать за собой при выгрузке.

Например, кнопку можно объявить так:

```java
public void registerKeybinds(KeybindRegistry keys) {
    keys.register("toggle", "Включить мой мод", 70); // F, код GLFW
}
```

Само действие пишется отдельно в `onInput`: состояние F можно проверить через `input.keyDown(70)`. Метод сообщает, что кнопка удерживается, поэтому для одного переключения на нажатие запоминайте её предыдущее состояние. Одна регистрация кнопки действие за вас не выполнит.

Снимок ввода содержит только часть клавиш (пробел, A, C, D, E, F, Q, R, S, W, X, Z, Shift, Ctrl). Для остальных кнопок нужен хук `input.key.v1` или собственный опрос GLFW — подробности в [справочнике SDK](docs/SDK.md).

API лежит в [`sdk/api/szmods/api`](sdk/api/szmods/api), пример — в [`sdk/example`](sdk/example). К внутренним классам игры сразу лучше не лезть: там всё привязано к версии клиента.

Полное описание — [моды и SDK](docs/SDK.md): манифест, порядок колбэков, настройки, HUD, ввод и таблица хуков `onClientHook`.

Подробности запуска — [здесь](docs/QUICKSTART.md), текущие ограничения — [здесь](docs/STATUS.md). Баги и предложения кидайте в Issues: что делали, что ожидали и что получилось.

### Аномалии

Настройки каждой аномалии открываются на F в режиме разработчика и сохраняются в самом объекте карты. У батута также доступны сила, перезарядка и режим импульса. [Как настраивать](docs/ANOMALIES.md).
