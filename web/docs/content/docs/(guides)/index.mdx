# Быстрый старт

Этот раздел — минимальный путь от чистого компьютера до работающего локального
сервера и первого мода. Для разработки SDK переходите в раздел [SDK](/docs/sdk).

## Что понадобится

- Windows 10/11 для готового лаунчера и клиента.
- Git и Python 3.10+ для сборки из исходников.
- JDK 17: `java` и `javac` должны быть в `PATH` или задан `JAVA_HOME`.
- Исходная карта с сервера: распакуйте её рядом с папками `Client` и `Server`.
  Нужны `Map/region` и `Map/registry.json`.

<Callout title="Важно">
  Клиентские классы и Java входят в локальный комплект. Из установленной игры
  берутся только ресурсы. Не смешивайте файлы из разных вариантов установки.
</Callout>

## Вариант 1. Готовый установщик

1. Скачайте свежий `BSCPCRAFT.exe` из раздела Releases.
2. Запустите установщик из отдельной папки.
3. Выберите корень установленной игры.
4. Оставьте рабочую ветку `main` и установите игровые файлы.

Поддерживаются две структуры игры:

- лаунчер: `classes.jar`, `assets`, `modassets/assets/bundle/configs.xeon`;
- Steam: `assets`, `modassets` и `bin_ru` или `bin_global` с `classes.jar` и
  `patchassets/assets/bundle/configs.xeon`.

<Callout>
  При выборе корня Steam лаунчер берёт целый `bin_ru`, а если его нет — целый
  `bin_global`. Файлы `bin_ru` и `bin_global` не смешиваются.
</Callout>

Если локальная установка уже была, закройте игру и сервер, запустите новый
установщик и выберите прежнюю папку. Клиент обновится, карта и персонажи
останутся на месте.

## Вариант 2. Сборка из исходников

Все команды выполняются из корня checkout.

```sh
python scripts/audit_public.py
python scripts/build.py test
```

`build.py test` собирает сервер, SDK и мод автодополнения, затем запускает
серверные тесты. Результат пишется в `build/verification.json`.

<Callout title="Тесты — не игровой запуск">
  Успешная сборка и тесты не доказывают вход в мир или работу сетевой сессии.
  Игровой прогон выполняется отдельно.
</Callout>

## Запуск своего сервера

Для запуска нового `server.jar` нужна совместимая приватная папка `Server` и
исходная карта.

```sh
python scripts/import_private_resources.py --server-jar "C:/LocalGame/Server/server.jar"
python scripts/build.py server --private-resources
python scripts/run_server.py --bundle "C:/LocalGame/Server" --map "C:/LocalGame/Map"
```

Импортёр копирует шесть закреплённых ресурсов и проверяет SHA-256. Классы и
пользовательские сохранения не копируются. Состояние нового сервера хранится в
`.local/server-state/data`, исходная карта читается только для чтения.

По умолчанию сервер слушает `127.0.0.1`:

| Назначение | Порт |
| --- | --- |
| Игровой HTTP | 29544 |
| Gateway | 29545 |
| World | 29546 |
| Admin health | 29644 |

Другой адрес задаётся через `--host`, базовый порт — через `--port`. При смене
порта также меняются `+1`, `+2`, `+100` и `+104`.

<Callout title="После тестов">
  `build.py test` пересобирает `server.jar` без игровых ресурсов. Перед игровым
  запуском снова выполните `build.py server --private-resources`.
</Callout>

## Первый мод

```sh
python scripts/build.py sdk
```

В `build/` появятся `mod-api.jar` и `hello-mod.jar`. Положите `hello-mod.jar` в
папку `mods` совместимого клиента и перезапустите его. Подробности — в
[SDK](/docs/sdk) и [сборке мода](/docs/sdk/build).

## Если что-то не запускается

- `resident_map_marker_binding` — сохранения привязаны к другой карте. Верните
  прежнюю карту или создайте новый мир с отдельной папкой данных.
- `Native memory allocation (malloc) failed` — системе не хватило памяти вне
  Java heap. Закройте лишние приложения и проверьте файл подкачки.
- Код `-1` без лога ничего не объясняет. Приложите `Client/logs/client-*.log`
  и `hs_err_pid*.log`, если он появился.
- `server_data_already_owned` — папку данных уже использует другой сервер.
  Остановите его штатно; удаление lock-файла не заменяет остановку процесса.
