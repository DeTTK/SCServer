# Сборка и проверка

## Штатные команды

```sh
python scripts/build.py sdk                  # mod-api.jar + hello-mod.jar
python scripts/build.py command-completion   # command-completion.jar + тесты
python scripts/build.py test                 # SDK, сервер и серверные наборы
```

`build.py sdk` компилирует API без зависимостей и пример против готового
`mod-api.jar`. Имя `hello-mod.jar` фиксировано, даже если пример переименован.

<Callout title="Чего не хватает тестам">
  Тестов самого API нет. Контракт проверяется сборкой примера и мода
  автодополнения, а поведение хуков — ручным прогоном в совместимом клиенте.
  Успешная компиляция не доказывает, что мод загрузится или отрисуется.
</Callout>

## Свой мод без `build.py`

```sh
mkdir -p out
javac --release 17 -cp build/mod-api.jar -d out src/my/mod/*.java
cp src/my/mod/stalcraft-mod.properties out/
jar --create --file build/my-mod.jar -C out .
```

Проверьте архив:

```sh
jar --list --file build/my-mod.jar
```

В корне JAR должны быть `stalcraft-mod.properties` и классы мода. Копий
`szmods/api/*` и `szmods/runtime/*` там быть не должно.

## Установка

1. Закройте клиент.
2. Положите JAR в папку `mods` профиля.
3. Запустите клиент.
4. Проверьте `mods/loader-<pid>.log` и stderr.

Для временного отключения без удаления файла используйте
`mods/enabled.properties`:

```properties
my-mod=false
```

Если задано системное свойство `allowed-mods`, в списке должны быть только
разрешённые ID, включая ваш.

## Проверка перед публикацией

- [ ] `stalcraft-mod.properties` лежит в корне JAR.
- [ ] `id` уникален и соответствует `[a-z][a-z0-9_-]{0,63}`.
- [ ] `api=1`.
- [ ] `main` указывает на существующий класс с публичным конструктором.
- [ ] Класс реализует `szmods.api.ClientMod`.
- [ ] В JAR нет копии API или runtime.
- [ ] Мод проверен в совместимом клиенте, а не только собран.
- [ ] Ошибки в колбэках не роняют клиент.
- [ ] Долгая работа вынесена из игрового потока.

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| Мод не загрузился | Имя манифеста, `main`, `api`, `id` |
| Мод отключился после старта | Лог `DISABLED after <stage>`, исключение в колбэке |
| Нет HUD | Call site `hud.crosshair.v1`, регистрация `registerHud` |
| Не работают клавиши | Код входит в разрешённый набор `InputSnapshot` |
| Нет настроек | `registerSettings`, ID вкладки, `settings.properties` |
| Хук не сработал | `null` от другого мода, приоритет, отсутствие call site |

## Ограничения

- Мод работает только в совместимом клиенте.
- Внутренние классы игры привязаны к версии клиента.
- Reflection по обфусцированным именам пишите защитно: ищите метод по имени,
  аргументам, возвращаемому типу и `static`/`instance`, переживайте отсутствие
  класса.
- Загрузчик не изолирует моды по правам: мод видит классы игры и других модов.
- `stalcraft-mod.properties`, ID хуков, имена bridge-пакетов и системные свойства
  (`sz.mods.dir`, `sz.launcher.memory`, `allowed-mods`, `sz.vr.active`) — контракт.
