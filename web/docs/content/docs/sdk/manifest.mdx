# Манифест мода

Загрузчик ищет файл с именем **ровно** `stalcraft-mod.properties` в корне JAR.
Без него JAR пропускается, даже если классы и API корректны.

## Минимальный пример

```properties
id=hello-mod
name=Hello Mod
version=1.0.0
api=1
main=example.HelloMod
```

## Поля

| Поле | Обязательно | Правило |
| --- | --- | --- |
| `id` | да | `[a-z][a-z0-9_-]{0,63}` |
| `name` | нет | Подпись для людей; загрузчик её не читает |
| `version` | да | Любая строка, формат не проверяется |
| `api` | да | Ровно `1` |
| `main` | да | Полное имя класса в этом JAR |

<Callout title="ID должен быть уникальным">
  Совпадение `id` со встроенным модом или с другим внешним JAR отключает мод.
  ID входит в имя каталога настроек, поэтому менять его у существующего мода
  нельзя без потери сохранённых значений.
</Callout>

Класс из `main` должен:

- существовать в этом же JAR;
- реализовывать `szmods.api.ClientMod`;
- иметь публичный конструктор без аргументов.

`name` и `version` удобны для диагностики, но загрузчик на них не опирается.
Версия API несовместима между значениями: мод с `api=2` будет пропущен.

## Где искать мод

Загрузчик — `szmods.runtime.ModLoader`. Каталог задаётся системным свойством
`sz.mods.dir`, по умолчанию это `mods`.

- Сканируются все `*.jar` в каталоге, в порядке имени файла.
- Ошибка одного JAR не мешает загрузить остальные.
- `mods/enabled.properties` отключает мод без удаления файла: `id=false`.
  Отсутствие ключа означает `true`.
- Системное свойство `allowed-mods` указывает файл со списком ID через запятую.
  Если оно задано, загружаются только перечисленные моды.
- Лог пишется в stderr строками `[ExternalMods][<id>] ...` и в
  `mods/loader-<pid>.log`.

## Каталог мода

Каждому моду создаётся `mods/config/<id>/`. Загрузчик пишет туда
`settings.properties`, а сам мод может хранить свои файлы через
`ModContext.configDirectory()`.

```java
Path dir = context.configDirectory();
Files.createDirectories(dir);
Path cache = dir.resolve("cache.bin");
```

Не пишите в каталог клиента и не используйте абсолютные пути из конфигов:
профиль может быть перенесён.

## Упаковка

`stalcraft-mod.properties` должен оказаться в корне архива, рядом с пакетами
классов. Пример без сборщика:

```sh
mkdir -p out
javac --release 17 -cp build/mod-api.jar -d out src/example/HelloMod.java
cp src/stalcraft-mod.properties out/
jar --create --file my-mod.jar -C out .
```

Проверить содержимое:

```sh
jar --list --file my-mod.jar
```

В списке должны быть `stalcraft-mod.properties` и `.class`-файлы, но не должна
лежать копия `szmods/api/*` или `szmods/runtime/*`.

## Частые ошибки

| Симптом | Причина |
| --- | --- |
| JAR не появился в логе | Нет манифеста или он не в корне JAR |
| `api` не подходит | Значение не равно `1` |
| Класс не найден | `main` не совпадает с пакетом или класс не попал в JAR |
| Мод отключён | Дублируется `id`, стоит `enabled=false` или его нет в `allowed-mods` |
| Настройки пропали | Изменился `id` мода |
