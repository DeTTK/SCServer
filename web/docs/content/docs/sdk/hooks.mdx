# Хуки

`onClientHook(String hook, Object... args)` — единственный способ вмешаться в
родные пути рендера, камеры и ввода.

## Контракт

- `null` — «не вмешиваюсь», родное поведение продолжается.
- Первое непустое значение выигрывает, остальные моды этот хук уже не получают.
- Исключение отключает мод.
- Аргументы — родные объекты конкретной сборки клиента. Типы между версиями не
  стабильны.
- Загрузчик проверяет возвращаемое значение и при несоответствии молча
  откатывается на родное поведение.

<Callout title="Порядок">
  Общий порядок — порядок загрузки модов. Исключение: `camera.third-person.v1` и
  `camera.fov.v1`, где `fpv-drones` получает приоритет, чтобы полноэкранный вид
  дрона не перекрывался камерой от плеча.
</Callout>

## Хуки только из `mods/`

Эти хуки встречаются в исходниках модов, но не имеют call site в этом
репозитории. Их обслуживает совместимый клиент, и наличие/типы аргументов здесь
не проверяются:

`player.animation.v1`, `model.actor-visible.v1`, `model.body-visible.v1`,
`model.mesh-visible.v2`, `fp.body-visible.v1`, `camera.director-active.v1`,
`hud.arc.*`, `replay.*`, `weapon.workbench-*`.

Опираться на них в стороннем моде рискованно.

## Пакеты `szmods.bridge.*`

Сетевые пакеты модов объявлены в приватной части совместимого клиента, а не в
SDK. Мод создаёт объект по полному имени и отправляет штатным конвертом.

Используются: `CommandRequest`, `CommandCatalog`, `MedicineUse`, `FpvInput`,
`FpvSnapshot`, `PlayerAnimation`, `VehicleInput`, `VehicleSnapshot`, `VrWeapon`,
`VrWeaponReply`, `EnvironmentInput`, `EnvironmentSnapshot`, `NpcEditorInput`,
`NpcEditorSnapshot`, а также `LegacyAdapter`.

Со стороны сервера эти имена — часть контракта (`szserver.net.*`,
`docs/COMPATIBILITY_NAMES.md`). Переименование ломает установленные моды.

## Слой `szmods.runtime`

Компилированные моды обращаются к `szmods.runtime.*` напрямую:
`ModLoader.clientHook`, `NativeFlightHooks.actionBlocked`, `FpvPackets`,
`AnimationHooks`, `ClientHits` и т.п. Это полу-публичный слой: он есть в
исходниках и работает, но его сигнатуры не входят в API `1`.

- `ModLoader.clientHook(hook, args)` — вызвать хук из своего кода.
- `FpvPackets.rawCodec(packet)` — точка, по которой клиент решает, что пакет
  относится к моду. Патчи привязаны к имени и дескриптору; сигнатуру менять нельзя.
- `ClientHits.capture(shot)` / `write(shot, out)` — снимок попадания; сервер
  принимает повторную отправку только с тем же попаданием.
- `FpvAudioHooks.setListener(double[12])` — позиция, скорость, направление и
  «верх» слушателя для нативного аудио.
- `VrFrameHooks.interval(native)` — при `-Dsz.vr.active=true` отдаёт `0`, чтобы
  пейсингом управлял OpenXR.

## Javaagent

Три проекта (`network-replay`, `npc-director`, `world-environment`) кроме JAR
содержат `premain`-агент на `java.lang.instrument`, который правит байткод уже
загружаемых классов. Он подключается через `-javaagent:` в аргументах JVM, а не
через папку `mods`.

Такой агент опирается на конкретные имена и дескрипторы методов. Например,
агент NPC-директора перехватывает
`szmods.runtime.FpvPackets.rawCodec(Ljava/lang/Object;)Z`. Переименование или
смена сигнатуры тихо отключает патч. Для обычного мода используйте
`onClientHook`.
