# Доставка игровых файлов

Ветка `main` публикуется в `build-main`, ветка разработки `test` — в `build-test`. После успешных тестов GitHub Actions собирает игру и публикует подписанный список отдельных файлов. Стабильный EXE выходит в GitHub Releases из `main`.


Игрок получает изменения через Rust-лаунчер без Git и GitHub-токена. Загрузка привязана к одному commit build-ветки; подпись проверяется встроенным публичным ключом. Непрошедшая тесты или вытесненная более новым push сборка не публикуется. Источники и build-файлы не смешиваются.

Канал содержит полную установку, включая Java и карту. Подписанный `delivery.json` закрепляет корневой индекс основы и изменяемые файлы. Лаунчер устанавливает пустую папку или повторно использует совпадающие локальные данные; карта и Java не скачиваются заново при каждой правке. CI сохраняет большие объекты через частичное получение Git-дерева, без скачивания всей основы на каждый push. Исходники модов без воспроизводимого рецепта остаются source-only и не выдаются за доступные бинарные сборки.

Локальная проверка: `python scripts/delivery.py prepare`. CI дополнительно выполняет `python scripts/delivery.py publish`, используя `LAUNTEST_DELIVERY_PRIVATE_KEY` из Actions Secrets. В репозитории хранится только `public-key.txt`. Приватный ключ запрещён в исходниках, build-ветке и логах.
