# Размер персонажа

Встроенная возможность для кастомного клиента и Java-сервера. Собственный JAR подключается при запуске JVM; в папку `mods` ничего класть не нужно. Исходные игровые классы и ассеты на диске не заменяются.

## Команды

- `/scale 0.5` — уменьшить себя вдвое.
- `/scale 2` — увеличить себя вдвое.
- `/scale "Ник игрока" 2` — изменить другого игрока.
- `/scale reset` — вернуть обычный размер.

Команды доступны администраторам. Диапазон — от `0.25` до `4`. Нужно стоять на земле; изменение внутри транспорта запрещено. Перед применением сервер проверяет свободное место, включая коллизии объектов. При отказе размер не сохраняется.

## Как работает

Используется тот же стек преобразований и преобразование геометрии попаданий, что у мобов. Масштабируется весь рендер игрока с экипировкой и оружием. Физическое тело, его ширина, высота во всех родных позах, высота глаз и дистанция третьего лица используют общий коэффициент. Стопы остаются на месте. Проверка стены за камерой остаётся родной.

Ноги и нижняя часть тела первого лица масштабируются отдельным родным проходом вокруг стоп, включая локальные смещения и наклон таза. В первом лице меняется высота камеры; экранное отображение рук и оружия остаётся в родном пространстве камеры. Скелетные хитбоксы меняются отдельно от внешнего рендера, через родной расчёт геометрии. Серверные проверки ближнего боя, взрывов, областей, атак ботов и наезда учитывают размеры тела. Клоны наследуют коэффициент. В пакет регдолла передаётся его штатное поле масштаба.

Скорость пешего движения пропорциональна размеру: `0.25` — четверть скорости, `0.5` — половина, `2` — двойная, `4` — четырёхкратная. Общий родной множитель применяется после бонусов обычного движения и спринта; экипировка и расходники сохраняют своё влияние. При повторных снимках масштаб берётся от исходной конфигурации и не накапливается. Сброс размера и перезаход восстанавливают соответствующую скорость.



При изменённом размере граф первого лица получает нулевой вход физической скорости, сохраняя режимы ходьбы, бега и спринта. Граф третьего лица получает физическую скорость, делённую на размер. Сетевая скорость нормализуется до упаковки, чтобы гигант не упирался в предел сетевого поля. Обычные бонусы экипировки и переключение поз сохраняются.

Огнестрельный луч от первого лица начинается в позиции масштабированной камеры. От третьего лица он начинается на масштабированной высоте глаз персонажа. Вертикальный импульс прыжка умножается на корень из размера, чтобы при штатной гравитации высота прыжка менялась примерно пропорционально размеру.

## Сохранение и сеть

Размер хранится в журнале персонажа как необязательный `character_scale_v1`. Повреждённое значение заменяется на обычный размер при чтении и не блокирует вход. Изменение передаётся после сохранения, без постоянного потока пакетов каждый тик.

Обновлённый клиент сообщает о поддержке возможности. Сервер отправляет новые пакеты только таким клиентам. Старый клиент входит с обычным размером; сохранённое значение остаётся и восстанавливается при следующем входе с поддержкой, если хватает места. Для одинакового отображения участников клиентская часть нужна всем.

Снимки имеют ревизии, привязаны к текущему соединению; запоздавшее обновление не возвращает удалённого игрока. При несовпадении версии родных классов клиентская часть отключается с записью в лог.

## Сборка

Собственный код и общий протокол находятся также в `client-compat/character-scale` и `shared/player-scale`.

Из каталога репозитория:

```text
python scripts/build.py test
python scripts/build.py server --private-resources
python client-compat/character-scale/build.py --runtime C:/Local/Client/runtime
python scripts/build.py desktop
```

Проверено в игре на двух клиентах: размер, вид от первого лица, сетевое отображение, скорость и параметры графов движения. Стресс-тесты столкновений регдоллов разных размеров и огнестрельный урон по увеличенным игрокам отдельно не подтверждены. Места транспорта под гигантов не подгонялись.
