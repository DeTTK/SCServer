# Кейсы и ящики

Открываются из обычного инвентаря: нажмите на кейс и выберите открытие. Появится родное окно игры с результатом. Если у кейса предусмотрен ключ, положите подходящий ключ в рюкзак. Для нескольких кейсов нужно столько же ключей.

Работают обычные таблицы добычи, наборы без повторов до исчерпания набора, гарантированные награды и открытие нескольких кейсов. Предметы, количество, состояние и теги берутся из совместимого игрового каталога. Клиент не выбирает награду.

Кейс, ключ и добыча сохраняются вместе. При полном рюкзаке или ошибке создания предмета ничего не списывается. Повтор одного запроса в той же сессии не выдаёт добычу ещё раз. После перезапуска сохраняются и предметы, и счётчики наборов/гаранта.

## Что пока ограничено

- В проверенном каталоге доступны 271 из 275 ящиков. У `15095` отсутствует предмет `7969`, у `16648–16650` — `12122`. Эти четыре ящика не расходуются: сервер сообщает об отсутствующей добыче. Подменять её другим предметом не стали.
- Переброс и продажа результата за валюту не подключены. Сервер возвращает ноль доступных перебросов; выпавшие вещи сразу остаются в рюкзаке.
- Для старых таблиц, зависящих от ранга, используется высший ранг надетого снаряжения, минимум «Новичок».
- Для дополнительных наград счётчик неудач выбирает значение из кривой `probability`; `guaranteedRoll` принудительно выдаёт награду на соответствующей попытке. После выигрыша счётчик сбрасывается. Это серверная реализация по полям каталога: исходный серверный расчёт недоступен.
- Одна операция ограничена 500 ящиками и размером штатного пакета результата. Слишком большой результат отменяет всю операцию; откройте меньше ящиков за раз.

## Разработчикам

`LootboxCatalog` читает определения, проверяет ссылки и выбирает добычу. `LootboxOpening` составляет единую операцию инвентаря. `GameInventory` создаёт нативные предметы на рабочем потоке и сохраняет результат через журнал. `LootboxPackets` связывает это с родным окном клиента.

Таблицы — частный ресурс `szserver/inventory/lootbox-tables.json.gz`, а не файл в Git. Он экспортирован из загруженного совместимого клиента. Импортируйте его вместе с остальными ресурсами из свежего серверного JAR:

```sh
python scripts/import_private_resources.py --server-jar /путь/к/server.jar
python scripts/build.py server --private-resources
```

Хеш закреплён в `config/private-resources.lock.json`. Без этого ресурса исходники собираются, но открытие ящиков недоступно. Менять состав набора при уже сохранённых счётчиках без миграции нельзя: несовпадение хеша останавливает открытие, сохраняя кейс и ключ.

Проверки: `python scripts/build.py test`. Проверка с настоящим клиентом отдельно включает обычные кейсы, ключи, пять открытий сразу, ящики без рулетки, повтор запроса и холодный перезапуск.
