# Быстрый старт

## Скачать исходную карту

[Map-20261118.zip — 254 МБ](https://github.com/DeTTK/SCServer/releases/download/original-map-2026.11.20/Map-20261118.zip).
Это исходная карта без изменений с сервера. Распакуйте рядом с Client и Server.
Нужная структура: `Map/region` и `Map/registry.json`.

## Установщик: без сборки и настройки Java

1. [Скачайте BSCPCRAFT-Setup.exe](https://github.com/DeTTK/SCServer/releases/download/steam-compat-2026.11.22/BSCPCRAFT-Setup.exe).
2. Выберите папку установки, укажите установленную игру и свой ник.
3. Нажмите «Скачать, установить и играть». Дождитесь распаковки: в комплекте много маленьких файлов.

Он скачает около 1,3 ГБ, проверит SHA-256 и установит комплект в подпапку `Local`.
Java включена. JDK, Python и PATH не нужны. Свободного места нужно около 5 ГБ.
При обрыве загрузки повторный запуск с той же папкой продолжит скачивание.

После установки сервер и клиент запустятся сами. В следующий раз открывайте `Local/Играть.exe`.
Остановка — «Сохранить и остановить», сохранения — `Local/Server/data`.
Саму установленную игру нужно получить отдельно: установщик скачивает комплект локалки, который её использует.

### Какую версию игры выбирать

Выберите корень установленной игры. Поддерживаются две структуры:

- Из лаунчера: `classes.jar`, `assets`, `modassets/assets/bundle/configs.xeon`.
- Из Steam: `assets`, `modassets` и `bin_ru` или `bin_global`. В выбранном `bin_*` должны быть `classes.jar` и `patchassets/assets/bundle/configs.xeon`.

Не переносите `classes.jar` и конфиги вручную. При выборе корня Steam лаунчер берёт целый `bin_ru`, а если его нет — целый `bin_global`. Можно явно выбрать папку `bin_global`, если нужна она. Файлы разных вариантов не смешиваются.

Клиентские классы и Java уже входят в локальный комплект, из установленной игры берутся ресурсы.
Поддержка любых будущих ресурсов не гарантируется; точный номер совместимой версии пока не указан.

Если уже ставили локалку, закройте игру и сервер, скачайте свежий установщик по ссылке выше
и выберите прежнюю папку установки. Это обновит клиент, сохранив карту и персонажей.
Если запуск всё равно не проходит, приложите последний `Local/Client/logs/client-*.log`
и текст ошибки. По одному сообщению «не та версия» причину определить нельзя.

Для ручной распаковки есть [полный ZIP](https://github.com/DeTTK/SCServer/releases/download/local-ready-2026.11.20/BSCPCRAFT-local-20261119.zip).
В таком случае откройте `Играть.exe` в корне распакованной папки.

## Linux и Steam через Wine

Если видите ошибку «нужна папка с classes.jar, assets и modassets», хотя выбрали игру из Steam, обновите установщик. В старом не было поддержки структуры Steam.

Откройте свежий `BSCPCRAFT-Setup.exe` в том же Wine, где уже открывался старый установщик. Выберите прежнюю папку локалки — карту и персонажей он сохранит. Папку игры можно открыть в Steam через «Управление → Просмотреть локальные файлы».

В окне Wine Linux-путь `/home/имя/.local/share/Steam/steamapps/common/…` обычно выглядит как `Z:\home\имя\.local\share\Steam\steamapps\common\…`. Выберите корень игры с `assets`, `modassets`, `bin_ru`, `bin_global`. В Flatpak Steam путь может быть внутри `~/.var/app/com.valvesoftware.Steam/` — важны файлы внутри, а не название папки.

Следующие запуски — через `Local/Играть.exe` в том же Wine. Не подменяйте комплектную Windows Java системной Linux Java: в этой поставке клиент использует Windows DLL. Нативного Linux-клиента в комплекте нет.

Структура Steam и загрузка её ресурсов проверены на Windows. Полный игровой запуск этой сборки под Linux/Wine ещё требует проверки на Linux. Если упадёт, приложите свежие `Client/logs/client-*.log`, `Server/logs/*` и версию Wine/Proton.

## Разработка без игровых файлов

Нужны Git, Python 3.10+ и **JDK 17** с `java` и `javac` в `PATH` либо `JAVA_HOME`.
Команды выполняются из корня checkout; путь может содержать пробелы.

```sh
python scripts/audit_public.py
python scripts/build.py test
```

Сборка создаёт собственный `server.jar`, API и HelloMod. Тесты проверяют границы регионов,
CRC/повреждения и потоковое восстановление журнала под ограничением heap 64 МиБ.
Журнал на 98 МиБ создаётся во временном каталоге и удаляется после теста.
Итоги находятся в `build/verification.json`; их нельзя выдавать за проверку сетевого входа.

## Первый мод

1. Изучите `sdk/example/src/example/HelloMod.java` и `sdk/example/stalcraft-mod.properties`.
2. Измените ID, main class и сообщения.
3. Выполните `python scripts/build.py sdk`.
4. Для проверки в совместимом частном клиенте положите `build/hello-mod.jar` в его папку `mods`.

Callbacks API v1 описаны в `sdk/api/szmods/api/ClientMod.java`, справочник с манифестом, порядком вызовов и хуками — в [SDK.md](SDK.md).
`game` в контексте — внутренний объект конкретного билда, его ABI нестабилен.

## Игровой запуск через существующую проверенную поставку

Игровой комплект подключается отдельно; его получение и права на использование в этот репозиторий не входят.
Это тот же формат папок `Client`, `Server`, `Map`, который используется в текущей локалке.

```sh
python scripts/local.py configure --client-bundle "C:/LocalGame/Client" --server-bundle "C:/LocalGame/Server" --game "C:/Games/BSCPCRAFT" --map "C:/LocalGame/Map"
python scripts/local.py doctor
python scripts/local.py open-server
python scripts/local.py open-client
```

На Windows откроются штатные окна комплекта. В ServerManager выберите Map и IP компьютера.
В Launcher задайте этот IP:29545, логин и установленную игру.
Для LAN нужны TCP 29545/29546 и TCP/UDP 29547. Admin API оставляется на loopback.
Сервер останавливается кнопкой сохранения. Изменения мира и персонажи остаются в `Server/data`.

`local.py` запускает подключённый проверенный бинарный комплект. Он не подменяет его свежесобранным `build/server.jar`.
Для запуска нового source JAR используйте следующий раздел.
Разработчик не должен считать успешный запуск старого бинарника проверкой своих новых исходников.

## Запуск сервера из своих исходников

Нужна совместимая приватная папка `Server` из локальной поставки и исходная `Map`.
Скрипт не скачивает игру и не подключается к production.

```sh
python scripts/import_private_resources.py --server-jar "C:/LocalGame/Server/server.jar"
python scripts/build.py server --private-resources
python scripts/run_server.py --bundle "C:/LocalGame/Server" --map "C:/LocalGame/Map"
```

Импортёр извлекает ровно четыре ресурса по закреплённым SHA-256, без классов.
Новый JAR запускается из `build/server.jar`; игра и map читаются из внешнего комплекта.
Состояние нового сервера хранится отдельно в `.local/server-state/data`, оригинальная карта не меняется.
Один state защищён от параллельного запуска OS-lock. Консоль показывает серверные логи.
Для остановки нажмите Ctrl+C и дождитесь сохранения/завершения Java.

По умолчанию запуск локальный: игровой HTTP `127.0.0.1:29544`, gateway 29545,
world 29546, admin health `http://127.0.0.1:29644/health`.
Другой IP задаётся `--host`, базовый порт — `--port`; при смене порта меняются также +1/+2/+100/+104.
Launcher клиента должен использовать тот же игровой HTTP адрес.
Административный токен созданной базы остаётся в `.local/server-state/data/admin-token.txt`.

После `build.py test` серверный JAR снова будет без игровых ресурсов: перед игровым
запуском повторите `build.py server --private-resources`. Проверка run_server не даст запустить
JAR без нужных ресурсов. Отчёт smoke не означает проверки полноценного боя клиентом.

## Windows GUI из исходников

```sh
python scripts/build.py desktop
```

Используется системный .NET Framework C# compiler. Получатся `build/desktop/Launcher.exe`
и `ServerManager.exe`. Это GUI, а не полный установочный комплект: рядом должны быть
подготовленные Java, runtime, ресурсы и конфигурация из отдельной поставки.
Legacy `SZCustom` с подписанной загрузкой требует сертификат оператора, публичный ключ релизов
и встроенный compatibility agent. Эти материалы и данные рабочего сервиса не экспортируются.


## Если запуск остановился

`resident_map_marker_binding` — сохранения привязаны к другой карте или другому каталогу объектов. Такое бывает, если заменить `Map`, оставив прежнюю `Server/data`. Верните карту, с которой играли, либо запустите новую карту с отдельной папкой сохранений: при запуске через окно локалки укажите другой `data.directory` в `Server/server.template.properties`, а при ручном запуске — в используемом properties-файле. Старую `data` сохраните. Не удаляйте по отдельности `resident-map.json` или содержимое журнала — так можно испортить постройки.

`Native memory allocation (malloc) failed` в `hs_err_pid*.log` — системе не хватило памяти вне Java-кучи. Закройте лишние приложения и повторите запуск одного клиента. Если на диске и в системе всё ещё мало памяти, одного увеличения `-Xmx` недостаточно: оно может сделать хуже. Проверьте, что файл подкачки не отключён и на диске есть свободное место.

Код `-1` без лога ничего не объясняет. Нужны `Client/logs/client-*.log` и, если появился, `hs_err_pid*.log`. Ошибку сервера присылайте вместе с логом клиента за тот же запуск. Токены и пароли из конфигов не присылайте.
