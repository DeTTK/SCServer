# Item Editor и NBT

Сохранение Item Editor больше не требует, чтобы порядок байтов вложенных обвесов совпадал с порядком их чтения. Раньше 39 из 604 проверенных конфигураций оружия отклонялись с `native_stack_roundtrip`, хотя сама игра считала их допустимыми. Это воспроизведено на предыдущем выпущенном JAR.

Теперь редактор использует оригинальные полный стек, NBT reader/writer, конструктор импорта и фабрики. На время операции подключаются подготовленные фабрики предмета и вложений. Для простых состояний используется зарегистрированный нативный state codec без запуска ненужных визуальных конструкторов. Родные встроенные фабрики повторно не создаются, если уже зарегистрированы.

После импорта сервер записывает и снова читает стек оригинальными кодеками. Полный NBT до и после этой записи обязан совпадать, включая свойства, UUID и вложения; второе кодирование обязано быть стабильным. Допускается изменение порядка записи карты. Другие изменения состояния при этой нормализации отклоняются. Обычный сетевой декодер остальных операций остаётся побайтово строгим.

Оба пути сохранения редактора — поток предмета и NBT-конфигурация — проходят этот адаптер. JSON-теги выдачи также импортируются оригинальным NBT-кодом. Убраны проверка тегов по экспортированному списку, отдельное исключение для `failed_upgrades` и ручное восстановление бонусов артефактов. Фабрика сама определяет, какие теги понимает. Неизвестный игре тег не становится новым свойством сервера.

Для схронов заранее вызывается оригинальный загрузчик настроек. Компрессия использует одну закреплённую JNI-библиотеку процесса; оригинальный NBT-wrapper инициализируется без повторной загрузки DLL по голому имени. Режим среды после его инициализации восстанавливается. Методы NBT и игровые классы в установленном клиенте не изменяются.

Проверки прав, адреса, типа вещи и количества, сохранение внешнего UUID, занятость персонажа и единственная запись через журнал остаются. Расчёт идёт на inventory worker. При отказе исходный предмет не заменяется.

## Проверки

- 604 конфигурации оружия: полный импорт и отдельно заточка до +15, без изменения остальных свойств.
- 977 исходных и заполненных состояний экипировки, включая качество, износ и артефакты.
- 8787 доступных шаблонов каталога. Один служебный предмет, 16969, уже имел пустой невалидный fixture; его кодек остаётся явно недоступным. У предмета пути NPC оригинальный импорт добавляет пустой `PATH` — то же поведение отдельно воспроизведено настоящим клиентом. Списка исключений для этих предметов в реализации нет.
- Настоящий клиент: шесть пушек с вложениями, три сохранения обычным обработчиком Item Editor и три обработчиком NBT-конфигурации. Полный результат совпал с отправленной клиентом вещью; менялась только заточка. После перезапуска инвентарь совпал полностью.
- Проверена выдача через типизированные JSON-теги заточки и неудачных улучшений, регрессия красок/обликов, полный серверный набор, установщик и обновление обеих раскладок локалки.

Клиент работал скрыто, без звука и физического/raw-ввода. Вызывались штатные обработчики кнопок на игровом потоке; это проверка их реальных запросов, а не физическое нажатие мышью. Linux-клиент этим прогоном не проверен. Подробности: [отчёт](validation-native-item-editor-20261123.json).

## Обновление

Закройте игру и сервер, запустите свежий Setup и выберите прежнюю папку локалки. Удалять инвентарь и журналы не нужно. Сохранённые ранее обвесы не заменяются. Если старая операция была отклонена, повторите сохранение в редакторе после обновления. Уже потерянное до этой правки состояние автоматически не восстанавливается.
