# Переносимый мир, формат 2

Сервер принимает свойство `world.directory`. Относительный путь отсчитывается от каталога файла `server.properties`. Подготовленный мир можно переименовать или скопировать на другой диск. Для открытия нужны обычный игровой runtime и целевой реестр сервера той же совместимой сборки.

| Файл внутри мира | Назначение |
| --- | --- |
| `world.properties` | Версия, стабильное пространство имён для сохранений и SHA-256 исходных файлов в собственной копии карты |
| `Map/` | Собственные `region/r.*.*.szr`, реестр исходной карты, `object-codecs.json`, полные состояния тайлов и прочие файлы шаблона |
| `data/` | Персонажи, инвентари, журналы транзакций, параметры объектов и текущее состояние изменённых регионов |
| `data/resident-map/head`, `head.previous` | Ссылки на текущую и предшествующую согласованные публикации чанков и глобального состояния |
| `data/portable-commands-v1/` | После разделения старого смешанного журнала содержит журнал бизнес-операций и индекс для чтения старых квитанций и отмены команд |

При загрузке чанка сервер ищет его в опубликованном поколении. Для ещё не изменённого чанка читает свою копию в `Map/`. Активные чанки живут в ограниченном кеше. При сохранении владелец мира фиксирует ревизии и ссылки на неизменяемые снимки. Отдельный рабочий поток сериализует снимки, перепаковывает затронутые регионы, синхронизирует файлы и атомарно переключает корень. Изменение во время записи оставляет новую ревизию грязной. Автосохранение настроено на 300 секунд. Давление на кеш, выгрузка грязных чанков и штатная остановка могут вызвать более раннюю запись.

## Создание и перенос

Пример для PowerShell из каталога поставки сервера. В Unix разделителем classpath служит `:`. Первые два аргумента после имени класса определяют операцию и каталог назначения. Каталог назначения для создания и миграции должен быть новым.

```powershell
$cp = 'server.jar;lib/*'
java -cp $cp szserver.world.PortableWorld create Worlds/First MapTemplate registries/live-object-codecs.json
java -cp $cp szserver.world.PortableWorld migrate Worlds/Imported OldMap registries/live-object-codecs.json OldData
java -cp $cp szserver.world.PortableWorld verify Worlds/Imported
```

Остановите исходный сервер перед миграцией. CLI берёт его блокировку, копирует обычные файлы с проверкой SHA-256, учитывает оба формата привязки старого сервера и публикует подготовленный каталог атомарным переименованием. Для старого лаунчера сверяется историческая content-v2 привязка. Для обычного Java-сервера прежний путь остаётся текстовым идентификатором. При наличии resident-квитанции CLI проверяет привязку скопированных байтов до публикации. Для этой проверки используется целевой реестр `live-gameobjects.json` рядом с переданным файлом кодеков, либо реестр самой карты. Проверка рассчитана на штатную политику заблокированных отсутствующих чанков. Для внешнего каталога шаблонов объектов или нестандартного fallback рельефа миграция с несовпадающей привязкой завершится ошибкой. При сбое путь незавершённой копии указан в диагностике.

На первом старте сервер проверяет снимки и завершает переход старого состояния в нативные поколения до открытия игровых портов. Старый смешанный журнал служит входом однократного преобразования. Покрытые снимком правки карты после него читаются из регионов. По историческому идентификатору редактор может запросить квитанцию, а персонажи и транзакции по-прежнему используют свои журналы. Страницы отмены и квитанции редактора занимают дополнительное место по мере работы.

Для клона, резервной копии и восстановления копируйте остановленный мир целиком, включая манифест. Копируйте байты изменяемых файлов в независимые обычные файлы. Идентификатор карточки мира в лаунчере можно менять.

## Проверка и откат

`verify` сверяет SHA-256 файлов в `Map/` и контрольные суммы всех чанков и файлов состояния в текущем resident-корне при остановленном сервере. Семантику игровых кодеков и транзакционные журналы проверяет старт сервера. Сервер сообщает об ошибке чтения повреждённого чанка. При повреждении заголовка или проверяемого на старте корня может выбрать предшествующее согласованное поколение.

Для явного отката карты остановите сервер, сохраните копию мира и выполните команду ниже. Она проверяет предшествующее поколение целиком и атомарно публикует его в качестве текущего. Это откатывает изменения карты последнего поколения.

```powershell
java -cp $cp szserver.world.PortableWorld rollback Worlds/Imported
```

Файлы поколений и оба публикуемых заголовка записываются с `FileChannel.force(true)`. На Unix дополнительно синхронизируются записи каталогов. Windows-провайдер Java использует атомарное переименование и синхронизацию обычных файлов. Сохранность при физическом отключении питания зависит также от файловой системы и контроллера накопителя.
