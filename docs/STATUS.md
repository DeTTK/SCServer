# Статус SCServer на 18.11.2026

## Проверено

- Java 17: сервер, SDK и HelloMod собираются без игровой базы.
- 10 проверок границ/CRC регионов, 12 047 проверок потокового журнала и 5 проверок reflection-дескрипторов.
- Два WinForms GUI собираются на Windows.
- GitHub Actions: независимая сборка и тесты прошли на ubuntu-24.04 и windows-2022.
  [Первый подтверждённый запуск](https://github.com/DeTTK/SCServer/actions/runs/44363287299).
- Отличия исходной серверной сборки сопоставлены с эффективным порядком overlay JAR рабочей поставки.
  У различавшихся ClientStateAdapter, NativeCreatureModel и World декомпилированный код совпал.
  У GameServer совпали тела существующих обычных методов; различия затрагивали порядок и синтетические методы.
  Более новые проверки RegionTerrain и compactConfiguration в EnvironmentWire сохранены.
  Это сверка поведения исходников, а не утверждение побайтового равенства JAR.
- Выбор native grenade getters теперь учитывает возвращаемый тип; выбор поведения объектов/сидений также сохранён.
- Серверный JAR, собранный из исходников с четырьмя закреплёнными приватными ресурсами,
  запущен на исходной карте: healthy=true, ready=true, игровая HTTP-сессия выдана,
  штатная остановка завершилась с кодом 0. Рабочий сервер не менялся.

Результаты — в `validation-report.json`. Импорт игровых ресурсов идёт только в игнорируемую `.local`.
Они не входят в исходный архив и Git; JAR с ними также нельзя автоматически публиковать.

## Что ещё не проверено

- Полная игровая сессия клиентом против нового source JAR, сетевой бой, транспорт и миграция production save.
- Чистая сборка клиентского bootstrap и всех модов с приватным ABI: agents/hook recipes ещё нужно выделять по модулям.
- Полная ручная проверка происхождения каждого фрагмента.

Лицензия намеренно не выбрана. Полный запуск без внешних игровых файлов не поддерживается.
