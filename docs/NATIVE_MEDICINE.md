# Применение медицины

Медицина теперь подготавливается через настоящие фабрики установленной игры. В проверенном комплекте их **211**, включая `medicine_animated`, который раньше не попадал в каталог из-за проверки строки `type == medicine`.

## Что берётся из игры

| Участок | Штатный код |
|---|---|
| Параметры, категория, приоритет, длительность, кулдаун, лечение и банк статов | Конструкторы `1305711328` и его подклассов |
| Фазы анимированного применения, активный банк, ключ эффекта и остановка при полном здоровье | Фабрика `1321132729` |
| Допуск к быстрому применению и сортировка, включая силу лечения при равном приоритете | `272027518.char` / `272027518.try` |
| Ограничения режима и типа локации | `1305711328.case` и matcher `782505764` |
| Чтение запроса применения | Оригинальный пакет `1166767938` и его reader |
| Создание и сериализация эффектов | Builder `222945433`, компонент `1967986234`, кодеки `837608172` |
| Сложение медицинских и остальных временных банков | `1967986234.synchronized` |

Общий `NativeItemFactories` содержит загрузку resource graph и настоящих фабрик, ранее использовавшуюся косметическим адаптером. Проверки совместимости косметики сохранены. NPC получают медицинские определения через тот же адаптер; их административное добавление баффа остаётся отдельной операцией без расходования инвентаря игрока.

Границы ABI привязаны к полным сигнатурам методов. Проверяются хеши 16 классов медицины, запросов и эффектов. Холодные фабрики, разбор ресурсов и прогрев кодеков выполняются при подготовке, до запуска owner-потока. Reader пакета использует заранее созданный экземпляр: конструктор с клиентскими событиями не исполняется на каждом сетевом запросе.

## Проюз и сохранение

Клиент вызывает обычный игровой контроллер и отправляет штатный запрос. Дополнительный RPC `szmods.bridge.MedicineUse` удалён. Новый клиентский мод или подмена анимации для применения не нужны.

Обычные предметы применяются через существующую атомарную транзакцию: списание одного предмета, состояние эффектов и receipt жизненных показателей сохраняются вместе. Исходный адрес не заменяется поиском по номеру слота. Адрес склада нормализуется общей логикой инвентаря; доступ и ACK используют исходного владельца запроса.

Для анимированного предмета сервер читает фазы из настоящей фабрики. У проверенного предмета начало рабочей фазы — 800 мс, активная фаза — 2500 мс, общий срок применения — 3300 мс. При входе в рабочую фазу предмет списывается один раз и появляется `MEDICINE_ACTIVE` с настоящим активным банком и ключом фабрики. После завершения он сменяется обычным эффектом без повторного списания и перезапуска кулдауна. Смерть, смена руки и условие полного здоровья прекращают соответствующий цикл. Анимацией управляет штатный клиент.

Каждая отправка медицинской дельты получает отдельную ревизию, включая истечение активной фазы и появление следующего эффекта в одном тике.

У предмета может не быть категории. Такая категория не заменяется общей строкой `medicine` и не вытесняет эффекты других предметов без категории. Для серверного кулдауна используется отдельная идентичность предмета; прежний сохранённый кулдаун `medicine` учитывается до его окончания. В старом формате NPC-баффов, требующем строковый ключ, эта идентичность также используется внутренне.

Дополнительные поля сохранённого эффекта (`persistent`, `active`, `activeKey`) необязательны. Отсутствующая или JSON-null категория читается корректно, в том числе после сериализации настоящим журнальным Gson. `PERSISTENT` не подменяется флагом `KEEP_ON_DEATH`.

## Граница переноса

Серверный метод `1305711328.break(player, stack)` и серверные обработчики фаз в установленном клиентском дампе пустые. Полного оригинального серверного дампа нет. Поэтому авторитетный жизненный цикл, транзакции, часы и сохранение остаются реализацией этого сервера; это не заявление о восстановлении неизвестного серверного тела один в один.

Параметры еды, опьянения, токсичности и мгновенной стамины теперь также читаются из фабрики. Отдельные отсутствующие системы физиологии этим изменением не добавляются. Доступ проверяется для текущего стандартного мира (`default`, `OPEN_WORLD`), совпавшего с состоянием проверенного клиента. Например, предмет с matcher `ENCAGED` в этом мире не применяется.

Здоровье и стамина по-прежнему используют общий серверный жизненный цикл. Их полный перенос на нативные компоненты — отдельный пункт аудита.

## Проверки

`python scripts/build.py test` включает `MedicineUseTests`: выбор точного корня, быстрый выбор по подготовленным штатным данным, кулдаун, отсутствие выдуманной категории, переход активного эффекта в обычный, отмену, настоящий JSON-сериализатор журнала и адреса склада.

Проверка на приватном игровом комплекте включает сравнение всех 211 фабрик с запущенным клиентом, реальные штатные запросы применения, единственное списание, кулдаун, клиентские эффекты, фазы анимации и холодный перезапуск. Синтетические CI-тесты не заменяют этот прогон. Итоговые подтверждённые результаты фиксируются отдельно в validation-отчёте.
